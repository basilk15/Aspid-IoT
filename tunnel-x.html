Security that travels with the signal.

From the ESP32 to the receiving sink, each part of the path has a clear job.

01

Private before it leaves the device.

Telemetry is encrypted at the edge, so the data moving across the link is protected from the start.

02

Verified before it is used.

The receiving sink checks the session, order, and integrity of each protected frame before decoding its contents.

03

Fresh keys, steady connection.

In-band rekeying renews the protected session while the existing TCP connection stays in place.

Built from a working device-to-sink path.

The current reference implementation connects ESP32 clients to a C++ sink. It records accepted telemetry and gives the operator per-device rekey control.

The reference build supports five concurrent client sessions. Broader fleet scale and new hardware integrations are work for a deployment pilot.
